# 段分けの指示（形式ごとに台本を段に分け、記事とつなぐ）

読む人: 段分けを任されたエージェント。読む時: 作業を始める前に全部。

## 役割
あなたは広告の台本を「段（セクション）」に分けて記録する係。自分で意見や一般論を足さない。台本と記事に書いてある事だけを書く。

## 材料（全部このフォルダの中）
- `manifest.tsv` … 1行1広告。列: format / id / brand / days（配信日数）/ sec（秒）/ landing（飛び先URL）/ lp_file（`lp/` の中の記事HTML）/ txt（台本）/ sheet（8コマを横に並べた画像）
- `txt/<id>.txt` … 台本（whisper の文字起こし。英語以外もある）
- `sheet/<id>.jpg` … 動画から8コマ。見た目（Pixar 風・3D・クレイ・実写の顔・マイク等）はこれで確かめる
- `lp/<file>.html` … 飛び先。見出しは `python3 -I ../lpread.py lp/<file>.html 40` で出る。中身が出ない（JSで作るページ）時は `python3 -I -c` で本文の文字だけ抜いてよい。同じページを何度も読まない
- 書き方の見本: `../sections_生データ.txt`（記号と書き方をこれに合わせる）

## 記号
● = VSL の中で中身まで全部言う ／ ◐ = 名前・数だけ言って中身は言わない ／ ○ = 言わない
→記事 = 飛び先がその段をどう補ったか（繰り返した／足した＝研究・権威・証拠・比較表・客の声・保証 等）

## やること（広告1本ずつ）
1. sheet で見た目を確かめ、任された形式に本当に入るかを決める。入らない時は「形式ちがい: 本当は〇〇」と書いて段分けは続ける
2. 台本を段に分ける。段の名前は短い日本語（例: 書き出し・症状の自己チェック・本当の原因・思い込み崩し・仕組みのたとえ・成分の役割・時間で歩く・証拠の数・オファー・品切れ）。段ごとに ●◐○ と、台本の中の短い引用（英語のまま12語まで）を付ける
3. 飛び先の記事の型を1つ決める: リスティクル（N個の理由）／物語のアドバトリアル（1人称・体験）／権威の暴露記事／医者の VSL ページ／クイズ／悩み別ページ／商品ページ／オファーページ／トップページ。記事の段を見出しの順に並べる（最大15段）
4. 「VSL の段 → 記事の段」の対応を書く: VSL で ◐ にした段を記事のどこで中身まで言ったか、記事が新しく足した段は何か

## 形式ごとのまとめ（全部の広告が終わってから）
- 段ごとに「何本中何本に出たか」を数える（母数を必ず書く。例 8/10）
- 7割以上に出た段 = その形式の**型**。4〜6割 = よくある選択肢。それ未満 = その広告だけ
- 型の段を順番どおりに1行で並べる（例: 書き出し(症状) → 本当の原因 → 思い込み崩し → 成分 → オファー）
- 飛び先の型ごとの本数（例: 商品ページ 6・リスティクル 3・クイズ 1）と、飛び先の型によって VSL の ●◐ がどう変わるか（数で）
- 母数が10本に届かない時は「n=〇本でパターンとしては弱い」と書く

## 出力
`段_<形式名>.md` をこのフォルダに書く。見出しは次の順:
1. 結論（3行。この形式の型・飛び先の型・VSLと記事の分担）
2. 型（段の出現数の表）
3. 飛び先との対応（飛び先の型ごと）
4. 広告ごとの段分け（`### <brand> <id>（<sec>秒・<days>日）→ <記事の型>` の下に sections_生データ.txt と同じ書き方）
5. 形式ちがい・読めなかった物（台本が空・記事が404 等。0件と書かずに理由を書く）

## 禁止
- 台本に無い段を推測で足さない。読めなかった物は読めなかったと書く
- 褒める言葉・一般論・「〜と思われる」を書かない
- 終わったら返事は3行だけ（書いたファイル名・形式ごとの本数・型の1行）
