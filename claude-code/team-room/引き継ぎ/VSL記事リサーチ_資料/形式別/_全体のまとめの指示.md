# 全体のまとめの指示（形式 × VSLの型 × 記事の型）

読む人: 全部の段分けを合わせて数えるエージェント。読む時: 始める前に全部。

## 材料
- このフォルダの `段_*.md`（pixar・body3d・tiny・podcast・street・clay・chalk・vsl_前半・vsl_後半）
- 前の記録 `../sections_生データ.txt`（約40本。形式 A〜M。書き方は同じ）
- `manifest.tsv`（配信日数・秒）

## やること
1. 全部の広告を1つの表にする: 形式・id（前の記録で id が無い物はブランド名）・秒・日数・飛び先の型・VSL の段の並び（短く）。同じ広告が2つのファイルに出たら1回だけ数える
2. 形式ごとに本数を数え、段ごとに「何本中何本」を出し直す（前の記録と新しい分を合わせる）。7割以上＝型、4〜6割＝よくある、それ未満＝その広告だけ。10本に届かない形式は「あと何本」を書く
3. 飛び先の型ごと（リスティクル・物語のアドバトリアル・権威の暴露記事・医者の VSL ページ・クイズ・悩み別ページ・商品ページ・オファーページ・トップページ）に、全部の形式を合わせて:
   - VSL の段の ●◐○ がどう変わるか（数で。例: 成分 ● は商品ページ行き 18/25、リスティクル行き 5/14）
   - 記事が VSL の後に足した段（本数の大きい順。例 研究 15/20）
   - 記事の段の型（見出しの順で7割以上に出る並び）
4. 「この形式の VSL は、この型の記事とつながる」の表: 形式 × 飛び先の型の本数の表（行＝形式、列＝飛び先の型）
5. 見た目の形式（Pixar・3D・クレイ 等）と話の運び（物語・権威・時間で歩く 等）のどちらが記事の型を決めているかを、数で答える

## 出力
`_全体の対応.md` に書く。見出しの順:
1. 結論（5行まで。数を入れる）
2. 形式 × 飛び先の型の表（本数）
3. 飛び先の型ごとの VSL の分担と記事の段の型
4. 形式ごとの型（1行ずつ・n つき・足りない本数）
5. 全部の広告の表
6. 数え方で決めた事（同じ動画の扱い・形式ちがいの扱い・読めなかった物の数）

それとは別に、図を作るための数だけを `_図のデータ.json` に書く。形は:
{"formats":[{"key":"pixar","name":"Pixar風","n":10,"enough":true,"type_line":["書き出し","結果","オファー"],"landing":{"商品ページ":6,"リスティクル":3}}...],
 "landings":[{"key":"listicle","name":"リスティクル","n":20,"vsl_full":["原因","今の物の失敗"],"vsl_name_only":["成分"],"article_adds":[["研究",15],["人数",12]],"article_type_line":["…"]}...],
 "matrix":{"rows":[形式名…],"cols":[飛び先の型…],"cells":[[本数…]…]}}

## 禁止
- 推測で本数を作らない。読めなかった物は数に入れず、数えた母数を必ず書く
- 一般論・褒め言葉を書かない
- 返事は3行だけ（書いたファイル・全体の本数・結論の1行）
